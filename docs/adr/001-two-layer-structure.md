# ADR-001: 仓库采用「开发层 + 载荷层」双层结构

- **状态**：已采纳
- **日期**：2026-09-26
- **决策者**：模板维护者

## 背景

早期版本把「交付给用户的内容」与「模板自身的开发文档」都放在仓库根目录。带来一个真实问题：

当维护者在 TRAE 中打开仓库以优化模板时，TRAE 会读取根目录的 `AGENTS.md` 作为项目规则。由于该文件描述的是"四阶段业务流程"，AI 会误以为自己在做一个四阶段业务项目，并去读取根目录那个占位的 `PROJECT_STATE.json`，导致**上下文错位**，无法正确理解任务。

同时，若在根目录加入开发文档，又会与要交付给用户的文件混杂，难以区分哪些该交付、哪些不该。

## 决策

将仓库拆为两层：

- **开发层**（仓库根）：`AGENTS.md`（开发指引）、`README.md`、`docs/`、`scripts/`、`tests/`
- **载荷层**（`template/`）：所有交付给用户的内容

`scripts/install.sh` 通过路径自适应，同时支持在仓库内与全局模板目录内运行。

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| 双层结构（采纳） | 上下文彻底隔离；载荷边界清晰 | 脚本需路径自适应，结构略复杂 |
| 保持单层 + 加开发指引文件 | 改动最小 | 根 `AGENTS.md` 冲突仍在，需靠提示语规避，不可靠 |
| 用 `.trae/` 包住载荷 | 层次少 | 与 TRAE 自身配置目录语义冲突，易混淆 |

## 后果

- **正面影响**：维护者打开仓库时，AI 读到的是开发指引；用户安装时拿到的是流程规范。两者互不污染。
- **负面影响**：路径变长，脚本需处理两种运行位置；用户若直接 `cp -r` 需注意复制的是 `template/`。
- **后续动作**：`CHANGELOG.md` 记录该变更；`scripts/validate.sh` 增加「载荷中不得含开发层内容」的校验。
